# Speaking: общий шаблон сайта

Утверждён 3 октября 2026. Применяется к новым и перерабатываемым Speaking во всех уроках, уровнях и предпросмотрах. Рабочая реализация — `SpaceWhaleExerciseKit.speaking()` в `exercise-kit.js`; образец — Speaking layout в существующем каталоге Workspace.

## Что видит ученик

1. Короткое название на английском, жирным шрифтом.
2. Иллюстрацию, если она уже предоставлена.
3. Короткую ситуацию и конкретную коммуникативную задачу. Несколько смысловых частей можно оформить пунктами.
4. **Use:** — единственный заголовок опор. Для каждой смысловой группы: слова в строку через `·`, затем необходимые речевые модели.

Количество слов, моделей и групп зависит от задачи. Они не обязаны состоять из вопроса и ответа: возможны просьбы, предложения, описания и другие целевые конструкции. Порядок частей фиксирован. Не добавлять механические указания, если задача понятна без них. Опоры содержат только нужный для задания язык и не подменяют ответ ученика готовым образцом.

Каждая модель из `phrases` выводится отдельным абзацем обычного системного шрифта. Не соединять модели в сплошной текст и не выделять всю опору жирным. Нумерация моделей при необходимости входит в утверждённый текст; формы неправильного глагола можно вынести отдельной смысловой группой без нового заголовка.

Не добавлять Test, Words, Useful language, Useful phrases, переводы, отдельные панели, раскрывающиеся опоры, ответы, заметки преподавателю и кнопки проверки/пропуска. Навигация между заданиями остаётся штатной навигацией Workspace. Правила для полей Writing и их проверки остаются отдельными.

Группа `use` может явно указать `emphasizeWords:true`: каждое целевое слово или сочетание выделяется полужирным, а разделители и модели остаются обычными. Без этого поля другие Speaking сохраняют своё оформление. В утверждённом B1 Module 2 слова выделены в обоих Speaking каждого урока; модели L1 идут без номеров, с `had (not)` и `would (not)`, без строки `get — got — gotten`.

## Заполнение данных

```js
const exercise = window.SpaceWhaleExerciseKit.speaking({
  id: 'permanent-exercise-id',
  title: 'Describe ...',
  image: null,
  task: {
    text: 'Короткая ситуация и что нужно сказать или выяснить:',
    bullets: ['Первая часть задачи.', 'Вторая часть задачи.']
  },
  use: [
    {
      words: ['word', 'word'],
      phrases: ['Target phrase ...', 'Response pattern ...']
    }
  ]
});
```

`task.text` и хотя бы одна непустая группа `use` обязательны. `bullets` можно опустить. В группе можно оставить только слова или только модели, если этого достаточно. Не добавлять поля для заголовков, кнопок, переводов, HTML, CSS, комментариев или ответов: проверка их отклонит. Общий рендерер выводит весь текст безопасно как текст.

Для готовой картинки заменить `image: null` на:

```js
image: {
  image: 'assets/lesson-media/.../picture.webp',
  alt: 'Краткое описание изображения',
  imageWidth: 1200,
  imageHeight: 800
}
```

Ширину и высоту брать из реального файла. При отсутствии картинки предусмотренный слот скрыт: нет рамки, технической надписи или запроса несуществующего файла. Допускается объект `{imagePending: true, assetId: 'stable-media-id'}` для связи с будущим файлом; его слот также не создаёт пустое видимое пространство. Изображение всегда появится между названием и задачей. Не генерировать и не подставлять изображение без соответствующего запроса.

Функция возвращает сериализуемое определение `kind: 'presentation', layout: 'speaking'`. Оно использует общий `validate`/`mount`, не имеет автоматической оценки или ответов и работает в обычном уроке, вложенной последовательности и каталоге. Исходные данные не изменяются. Стабильный ID упражнения сохраняется.

## Картинка рядом с опорами (18 октября 2026)

По явному запросу владельца предусмотрен вариант `arrangement:'image-support'` в той же фабрике. Картинка находится слева, **Use:** со словами и моделями — справа. При недостатке ширины рабочей колонки опоры переносятся целиком под картинку; шрифт не уменьшается, изображение не обрезается. В этом варианте `task` можно опустить, если краткая инструкция полностью дана в `title`. Отдельные описания картинок, вопросы и повтор задания не добавляются.

Если опоры слишком объёмны для боковой колонки, предусмотрен `arrangement:'image-support-below'`: картинка занимает доступную ширину до 640px внутри существующей рабочей колонки, Use находится ниже. Пропорции исходного изображения сохраняются; поля рабочего пространства и размер шрифта не меняются. `task` также можно опустить при полной инструкции в `title`. Краткая боковая опора и большой блок под картинкой остаются вариантами одного S01, а не отдельными шаблонами урока.

Несколько картинок оформляются детьми обычного `progressive` stage. Общий заголовок принадлежит родителю; одинаковые заголовки детей скрываются штатным правилом. Стрелка преподавателя постепенно открывает следующие изображения, сохраняя предыдущие. У каждого изображения свои опоры Use, без OK, Skip, раскрывающихся ответов или заметок. Все остальные Speaking сохраняют исходный порядок и обязательное `task.text`.

## Порядок работы следующих чатов

Если владелец явно просит пока разместить только готовую картинку, допустим `arrangement:'image-only'` в той же фабрике: `title:'Speaking'`, реальный объект `image`, без `task` и `use`. Проверка требует изображение и отклоняет добавленные `task`/`use`. Никакие инструкции, пустые опоры или подписи-заглушки не создаются. Этот промежуточный вариант не меняет законченные задания. При повторе в начале и конце урока содержимое берётся из одного источника, а постоянные ID различаются, чтобы раскрытие в одном месте не влияло на другое.

Составить содержимое полей по вводным → показать текст задания → получить подтверждение, если оно ещё не дано → заполнить этот шаблон → проверить и опубликовать. Для изменения самого формата требуется явный запрос пользователя. Для других типов упражнений использовать их готовые шаблоны из `TEMPLATE_FACTORY.md`; Speaking не заменяет Matching, Listening, Writing или проверяемые задания.

Старые упражнения с произвольными блоками поддерживаются для совместимости. При переработке конкретного Speaking переводить его на общий шаблон, сохраняя согласованную задачу и данные ролей. Не удалять молча содержимое старых уроков и не считать весь архив Speaking уже перенесённым.
