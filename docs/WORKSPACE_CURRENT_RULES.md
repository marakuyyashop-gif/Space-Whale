# Рабочая область уроков — действующие правила

Версия: 2026-10-12  
Статус: действующая инструкция для рабочей области уроков.

## 1. Граница текущей работы

Сейчас меняем только рабочую область, в которой проходят уроки: общие шаблоны упражнений, их оформление и размещение готовых сценариев.

Главная страница, личные кабинеты, домашняя работа, оплата и другие части продукта остаются отдельными направлениями. Их существующее поведение не меняем без отдельной задачи.

Старые уроки сейчас не переносим на новую структуру и не переписываем: они будут перерабатываться позднее по готовым сценариям.

## 2. Как готовый сценарий попадает на сайт

Входные данные — утверждённый сценарий, в котором указаны уровень, модуль, урок, порядок, код упражнения, точный текст, ответы и нужные медиа.

При размещении на сайте:

1. Найди общий шаблон, соответствующий коду упражнения.
2. Заполни только предусмотренные поля шаблона данными сценария.
3. Размести упражнение по указанному адресу курса.
4. Сохрани постоянные ID упражнений, ответов и медиа.
5. Проверь результат в рабочей области и в связанных teacher/student views.

На этом этапе не нужно заново читать CARD, выбирать методику или придумывать содержание. Если подходящего шаблона нет либо в сценарии не хватает обязательного поля, нужно кратко назвать конкретный пробел, а не достраивать упражнение по своему усмотрению.

## 3. Один общий «ствол» для всех уроков

Уроки хранят содержание, а не собственную верстку и стили.

- `workspace-catalog.js` — порядок и адреса курса.
- `exercise-theme.css` — общий шрифт, размеры, цвета и визуальные токены упражнений.
- `exercise-kit.css` — общие макеты и оформление механик.
- `exercise-kit.js` — общая отрисовка, проверка и взаимодействие.
- lesson/content files — только тексты, ответы, ID и ссылки на медиа.

Не создавай отдельные HTML/CSS-компоненты для конкретного урока. Изменение общего шаблона или токена должно автоматически применяться ко всем упражнениям, использующим этот шаблон.

## 4. Как обновлять инструкции

Новое прямое решение пользователя заменяет соответствующее старое правило в основном месте. Не добавляй ниже второй противоречащий вариант.

Сохраняй остальные действующие требования, которых изменение не касается. Git history служит архивом прежних версий; отменённые правила не нужно оставлять среди действующих.

Файл удаляется только после проверки, что он не используется кодом, ссылками или совместимостью старых маршрутов. Не называй весь сайт перенесённым или унифицированным после изменения одного шаблона.

## 5. Визуал: текущая граница

Новая визуальная система ещё не утверждена. Направление для следующего этапа: нейтральная светлая рабочая область, высокая читаемость, минимум цветных поверхностей, единая типографика и более спокойные формы без обязательного сохранения старого неоморфизма.

До утверждения типографики, палитры и образца реального упражнения не проводить глобальный визуальный rollout. Дизайн выбираем на настоящих элементах рабочей области, после чего применяем через общие токены и шаблоны, а не вручную в каждом уроке.

## 6. Ближайший порядок работы

1. Убрать только подтверждённые временные страницы, устаревшие дубли документов и противоречащие им активные указания.
2. Выбрать типографику и нейтральную палитру на одном реальном экране урока.
3. Утвердить общий каркас рабочей области и бокового меню.
4. Разбирать и обновлять механики по одному общему шаблону.
5. После утверждения шаблона применять его централизованно ко всем новым и перерабатываемым урокам.
